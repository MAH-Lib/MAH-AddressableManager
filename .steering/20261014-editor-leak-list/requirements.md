## 1. 変更・追加する機能の説明

寿命回収時に「明示 `Release` されずに回収されたチケット」（リーク）を、ログに流すだけでなく、Editor 限定で**確保元ごとに集約して溜め**、デバッグウィンドウの新しいタブ「リーク」で一覧表示する。あわせて、スタックトレースから呼び出し元のコードの該当行へ**ジャンプ**できるようにする。ジャンプは、既存の「実行時状態」タブのチケットのスタックトレースにも共通部品として適用する。

背景：リーク警告の記録側（確保時のスタックトレース・「呼び出し元に返し終えたか」の判定）は実装済みだが、ログは流れて見逃される。自動回収に頼った実装を是正させるという方針（設計仕様書 3.9(3)）を機能させるには、溜めて見返せる一覧が必要。

決定済みの仕様：

- **蓄積は確保元で集約する**。単体は（`AssetKey`・型・寿命の種類・スタックトレース）、Label 一括は（Label・寿命の種類・スタックトレース）が同じものを1行にまとめ、発生回数・最終発生時刻・最終発生スコープ名・最終発生の通し番号を持つ（同じ確保元のリークが大量に発生しても、行が増えないため）
- **「表示をクリア」はタブ側の既読扱い**。Runtime の記録は消さず、タブが「クリア時点の基準」を持って、それ以降の発生分だけを表示する（窓口を読み取り専用のまま保つため）
- **ログファイルに出力できる**（2026-10-14 追加）。「リーク」タブの「ログ出力」ボタンで、表示中の内容をテキストファイルに書き出す。「ログ出力 → 表示をクリア」の流れで、クリアした後でも、区間ごとの記録を後から確認できる。あわせて、**Play の終了時に自動で出力する**設定（既定は OFF）を用意する
  - 手動の出力は、日時付きのファイル名で**溜める**。自動の出力は、固定名 `AddressableLeaks_LastPlay.txt` に**上書き**し、前回分を `AddressableLeaks_LastPlay-prev.txt` に1世代だけ残す（Unity の `Editor.log` / `Editor-prev.log` と同じ）。自動出力は、リークが0件のときも「リークはありませんでした」と書いて上書きする
  - 出力先のフォルダは、`AddressableEditorSettingsSO` で変更できる。既定は、Unity の他のログと混ざらないよう、`Logs/` の下に1階層かませた `Logs/AddressableManager/`
- **寿命スコープの名前は、リークの発生時点で記録する**。Owner は Watcher に登録中の GameObject 名、Scene は `sceneUnloaded` で受けた Scene 名。リークは寿命の終了時に起きるため、後から Editor 側で引くと、ほぼ必ず「破棄済み」になるため

## 2. ユーザーストーリー

- 実装担当者として、Release の呼び忘れを見逃さないために、リークをログではなく一覧で見返したい
- 実装担当者として、同じ箇所のリークが何回起きたかを把握するために、確保元ごとに集約された回数を見たい
- 実装担当者として、呼び忘れを直すために、リークした確保の呼び出し元のコードへ、スタックトレースからジャンプしたい
- 実装担当者として、どの Owner・どの Scene の寿命で起きたかを知るために、リーク発生時のスコープ名を見たい
- 実装担当者として、修正後の確認のために、既に見た分を「表示をクリア」で隠し、新しく起きたリークだけを見たい
- 実装担当者として、「実行時状態」タブのチケットのスタックトレースからも、同じ操作でコードへジャンプしたい
- 実装担当者として、表示をクリアした後や Play を止めた後でも、リークを見返せるように、「ログ出力」でファイルに残したい（出力してからクリアする使い方）
- 実装担当者として、Window を開いていなくても記録が残るように、Play の終了時にリークを自動でファイルに出したい
- 実装担当者として、プロジェクトの都合に合わせて、ログの出力先と、自動出力の ON / OFF を設定で変えたい
- レビュアーとして、本番ビルドの挙動・コストが変わらないことを確認するために、記録と表示がすべて Editor 限定であってほしい

## 3. 受け入れ条件

### リークの記録（Runtime・Editor 限定）
- [ ] 呼び出し元にチケットを返し終えた（`AccIsDelivered`）チケットが、Scene / Owner 寿命で回収されると、リークとして記録される
- [ ] ロード中（返す前）に寿命が終わった分と、明示 Release 済みの分は、記録されない
- [ ] Label 一括ロードのリークは、まとめチケット1枚につき1件だけ記録される（中身の件数分は記録されない）
- [ ] 同じ確保元（キー・型・寿命の種類・スタックトレースが同じ）のリークが繰り返されると、行が増えず、回数が加算され、最終発生時刻・最終スコープ名・通し番号が更新される。スタックトレースが違えば別の行になる。単体と Label 一括は別の行になる
- [ ] Owner のスコープ名は、回収時に GameObject が生きていれば GameObject 名で記録される。取れない場合（ポーリングで破棄後に見つかった場合など）は名前なしで記録される。Scene のスコープ名は、アンロードされた Scene の名前で記録される
- [ ] 従来どおり、リーク警告のログも出る（ログの内容・出る条件は変わらない）
- [ ] 窓口 `IAddressableDebugReader` に `CopyLeaksTo` が追加され、取得済みの `Snapshot` は、取得後に Model が変わっても値が変わらない

### 「リーク」タブ
- [ ] ツールバーに「実行時状態」「リーク」の2タブが並び、「リーク」タブに、先頭の件数（リーク N 回・確保元 M 件）と「表示をクリア」ボタンが表示される
- [ ] 行は、最終発生の新しい順に並び、回数・キー（Label 一括は Label と件数）・型・寿命の種類のマークとスコープ名・最終発生時刻・最初の利用者フレームへのジャンプボタンが表示される。スコープ名が無いものは、ID / handle で表示される
- [ ] 行を開くと、スタックトレースがフレームごとに表示され、全文をコピーできる
- [ ] 「表示をクリア」を押すと一覧が空になり、その後に起きたリークだけが表示される（行ごとの回数も、クリア以降の分だけ数える）。Runtime の記録は消えない
- [ ] Play していない間は「未起動」と表示され、Play の終了で一覧・開閉の状態・クリアの基準が破棄される
- [ ] ウィンドウ上に、Release・強制回収・Runtime の記録を消す操作が存在しない

### ログ出力（手動）
- [ ] 「リーク」タブの見出しに「ログ出力」ボタンがあり、「表示をクリア」の左に並ぶ
- [ ] 「ログ出力」を押すと、ダイアログを出さずに、設定の出力先フォルダへ、`AddressableLeaks_yyyyMMdd_HHmmss.txt` が作られる。作られたパスが Console に出る
- [ ] ファイルには、画面に表示中の行（前回の「表示をクリア」以降の分。回数もクリア以降の回数）が、画面と同じ順（最終発生の新しい順）で書かれる
- [ ] ファイルの中身は、見出し（出力日時・リーク N 回・確保元 M 件）と、行ごとの次の項目である：回数／キーと型（Label 一括は Label と件数）／寿命とスコープ名（名前が無いときは ID・handle）／最終発生時刻／呼び出し元（最初の利用者のフレーム。無ければ「不明」）／スタックトレース全文
- [ ] 同じ秒に続けて出力しても、ファイルは上書きされず、連番が付いて別のファイルになる。手動で出力したファイルは、自動では削除されない
- [ ] 表示中の行が0件のときは、「ログ出力」ボタンが押せない
- [ ] 出力先フォルダが無ければ作られる。書き込めないとき（権限・不正なパス）は、Console に警告が出て、Editor は止まらない

### ログ出力（Play 終了時の自動）
- [ ] SO の自動出力が ON のとき、Play の終了時（`ExitingPlayMode`）に、そのセッションの全リーク（タブの「表示をクリア」とは無関係）が、出力先フォルダの `AddressableLeaks_LastPlay.txt` に書かれる。Window を開いていなくても動く
- [ ] 書き込みの前に、既存の `AddressableLeaks_LastPlay.txt` が `AddressableLeaks_LastPlay-prev.txt` に移る（既存の `-prev` は消える）。つまり、最新の2回分だけが残る
- [ ] リークが0件でも、「リークはありませんでした」（出力日時つき）で `AddressableLeaks_LastPlay.txt` が上書きされる
- [ ] 自動出力が OFF のときは、何も書かれない。Manager が無いとき（Play していない）は、何もしない
- [ ] 自動出力が削除・移動するのは、固定名の2ファイル（`AddressableLeaks_LastPlay.txt`・`-prev`）だけ。同じフォルダの手動出力のファイルや、他のファイルには触れない

### ログ出力の設定
- [ ] `AddressableEditorSettingsSO` の Inspector に「リーク」の項目が加わり、出力先フォルダ（既定 `Logs/AddressableManager`）と、Play 終了時の自動出力（既定 OFF）を変えられる
- [ ] 出力先は、相対パスならプロジェクトのルート（`Assets/` の親）から、絶対パスならそのまま使われる。空白のときは、既定値に戻る
- [ ] 既存の `AddressableEditorSettings.asset` は、そのまま読み込め、新しい項目が既定値で入る（マイグレーション不要）

### スタックトレースからのジャンプ（共通部品）
- [ ] ファイルと行の情報があるフレームはリンクとして表示され、押すと外部エディタで該当ファイルの該当行が開く
- [ ] ファイルの情報が無いフレームは、ジャンプ不可の薄い表示になる（例外にしない）
- [ ] 「最初の利用者フレーム」は、モジュール内（`Runtime/` 配下・`Library/PackageCache/` 配下）を飛ばした、ファイル情報のある最初のフレームになる
- [ ] 「実行時状態」タブのチケットのスタックトレースも、同じ共通部品で表示され、ジャンプとコピーができる

### 構造
- [ ] Runtime 側の追加（`LeakRegistryModel`・`LeakSnapshot`・記録の呼び出し・窓口のメソッド・Manager の注入）が、すべて `#if UNITY_EDITOR` で囲まれ、本番ビルドに含まれない
- [ ] `LeakRegistryModel` は Manager が生成し、`LoadingController` と `AddressableDebugReader` へコンストラクタ注入される（Controller 内で new しない）
- [ ] 窓口に Model を書き換えるメソッドが無い。Editor 側が、窓口と `Snapshot` 以外の internal 型を使っていない
- [ ] コピー処理が `List` の再利用で行われ、`ToArray()` / `ToList()` を使っていない。`Draw` の中で文字列・`GUIContent`・`GUILayoutOption` を毎回作っていない
- [ ] ログ出力は Editor 側だけで行い、Runtime の記録・Registry・窓口のインターフェイスに変更を加えていない（読み取りは既存の `CopyLeaksTo`）。出力の文字列の組み立ては、Unity 非依存のクラスに分かれている
- [ ] `Core/Loading/` のファイルから `Core/DebugReader/` を `using` していない。`LoadingController.ReleaseLifetime(LifetimeScopeId)` のシグネチャと、解放経路（`ReleaseInternal`）が変わっていない

### テスト・ドキュメント
- [ ] 蓄積（集約・区別・更新・コピー）、Controller の記録の有無（返し済み／ロード中／明示 Release 済み／まとめチケット／スコープ名）、スタックトレースの解析、ログ出力（文字列の組み立て・出力先の解決・ファイル名・自動出力の上書きと1世代の入れ替え・手動ログが消えないこと・設定の既定値と補正）に対する EditMode テストが追加され、既存テストを含めてすべて通る
- [ ] spec の 8章に機能2の節（8.2）が、8.1 と同じ構成で追記され、状態表が更新されている。新しい型名が spec・design・loading-spec・図で表記揺れなく一致している

## 4. 制約事項

- Editor 拡張は**読み取り専用**。窓口に書き換えメソッドを足さず、手動 Release・強制回収・記録の消去のボタンを作らない（CLAUDE.md「設計の絶対ルール」）
- Controller・Model はピュアC#のまま。`LeakSnapshot` に `UnityEngine.Object` の参照を持たせない（スコープ名は、記録時に文字列で持つ）
- 3つの Controller は互いを参照しない。窓口は機能フォルダの外（`Runtime/Core/DebugReader/`）に置く例外（conventions 7.4）に従う
- DI コンテナ・R3 に依存しない（Manager の手動 `new` と注入）
- 記録・表示処理は `#if UNITY_EDITOR` で本番ビルドから完全に除外する。一時コレクションを都度確保しない。クロージャ・ラムダを毎フレーム生成しない
- 描画は IMGUI（既存の Editor コードと揃える）
- 既存の Runtime の挙動（解放経路・ログ・例外）を変えない。`LoadingController` のコンストラクタ引数の追加に伴い、生成箇所（Manager・テスト基盤）を更新する
- `Environment.StackTrace` の書式に依存する（ファイル情報の有無は環境で変わり得る）。解析できない行は、ジャンプ不可として扱う
- ログ出力は、読み取りだけを窓口から行い、ファイルへの書き込み以外の副作用を持たない。Runtime にファイル書き込み・イベントを足さない（設計仕様書 3.9 の pull 方針。自動出力は、Play 終了の直前に Editor 側が窓口から読む）
- ファイルの削除・移動は、自動出力の固定名の2ファイルに限る（パターンでの一括削除をしない）。ファイルが使用中などで失敗しても、例外を握って警告に留め、Editor・Play の終了を止めない
- CHANGELOG は更新しない（担当者の運用）。コードレビュー・手動検証・ドキュメントの最終確認は Claude の担当外

## 5. スコープ外（今回やらないこと）

- Runtime の記録の消去（窓口の書き換えメソッド）。「表示をクリア」はタブ側の既読扱いのみ
- Play 終了後の一覧の保持（Manager の破棄で消える。共通基盤の仕様のまま）
- リークの蓄積の件数上限と、蓄積側の設定項目。確保元で集約するため、件数は確保元の数で頭打ちになる（ログ出力の設定〔出力先・自動出力〕は、今回の追加として `AddressableEditorSettingsSO` に足す）
- ログの形式の選択（CSV・JSON）。テキストのみ
- 保存ダイアログでの保存先の選択（出力先は SO で設定する）
- リーク発生のたびのファイルへの追記（Runtime にファイル書き込みを入れない）
- 手動で出力したログの自動削除・件数上限（手動分は溜める）
- 自動出力で、リーク0件のときの動き（上書き）を変える設定（上書きしても直前の分は `-prev` に残るため、設定にしない）
- Play の停止そのものが原因で起きる回収（シーンの破棄）の出力。`ExitingPlayMode` はシーンの破棄より前のため、自動出力には含まれない（spec に注意点として書く）
- ロード中に寿命が終わった分のリーク扱い（リークではない。従来どおり Verbose ログのみ）
- 本番ビルド・実機でのリークの記録
- 一覧の検索・絞り込み・並べ替えの UI
- owner Watcher の可視化（機能3）・読み込み計測（機能4）・サイズ概算（機能5）
- `OwnerWatchRegistryModel` の窓口への注入（機能3で必要になった時点で足す。今回のスコープ名は、`LoadingController` が記録時に解決する）
