## 1. 変更・追加する機能の説明

自動登録と手動一括登録のレビューで見つかった指摘のうち、🔴・🟡 をすべて直す。🟢 は、実害（誤動作・リーク・警告漏れ）があるものだけ直す。

背景：本モジュールは UPM で他プロジェクトに配布する汎用モジュールで、自動登録はインポートのたびに利用者のプロジェクトで動く。レビューでは次の問題が見つかった。
- 誤動作：対象フォルダの名前を変えたあと、自動登録が古いパスで判定し続ける（🔴）。ウィンドウを開いたまま状態が変わると、古い計画のまま書き込める（🟡）
- 規約違反：`conventions.md` §1（フィールドは private）・§2（アクセサの中で関数を呼ばない）に反する箇所がある（🟡）
- Editor の固まり：ルールの対象外のインポート（`.cs` の保存を含む）でも、全エントリの走査が走る（🔴）。Inspector のキー入力のたびに重い処理が連鎖する。大量の警告が Console とウィンドウを埋める。サムネイルの読み込みが描画のたびに繰り返される（🟡）

主な内容：
- ルールのキャッシュを捨てる条件を直す（フォルダの移動・削除、スイッチがオフの間の変更）（🔴）
- 書き込む時点で、エントリが計画を作った時点と違っていたらスキップし、利用者に知らせる（🟡）
- ルールの対象外のインポートでは、AssetDatabase にも全エントリの走査にも触れない（🔴）
- Matcher の文字列の確保をなくす。Inspector・手動一括登録の入力は、確定してから反映する。プレビューは集めた結果を使い回す（🟡）
- ログの細かさが「まとめだけ」のとき、5件を超える警告を1件に要約する。ルール一覧の差分と警告は、見えている行だけを描く（🟡）
- conventions.md の規約に合わせる（🟡）
- 実害のある 🟢 を直す（競合の一覧でルールを GUID で選ぶ・Create メニューのキャンセルで SO が残る・`{Rule.Name` の警告漏れ・`Collect` のメッセージの上書き）

## 2. ユーザーストーリー

- 本モジュールを導入するプロジェクトの開発者として、対象フォルダの名前を変えても、自動登録が正しく動き続けてほしい
- 開発者として、スクリプトを保存するだけの操作で、Editor が自動登録のせいで固まらないでほしい
- 開発者として、手動一括登録のウィンドウを開いたまま、ほかの操作で状態が変わっても、確認した内容と違うグループ・アドレスに書き換えられたくない
- 開発者として、ルールの SO の Inspector にテンプレートを打つとき、1文字ごとに Editor が重くなったり、Console が警告で埋まったりしないでほしい
- 開発者として、大量のアセットに当て直したとき、警告が1件ずつ数千件出るのではなく、要約して見たい（全件が必要なときは、ログの細かさで切り替えたい）
- 本モジュールの保守者として、`conventions.md` の命名・アクセサの規則に沿ったコードにしたい

## 3. 受け入れ条件

### 正しさ（🔴・🟡）
- [ ] 対象フォルダの名前を変えたあと、その中に新しく置いたアセットが登録される。「ルールに当たらなくなりました」の誤った警告が出ない
- [ ] 自動登録のスイッチがオフの間にルールの SO を削除し、オンに戻したあと、削除したルールでは登録されない
- [ ] 計画を作ったあとに、同じアセットが別の操作で登録されていた場合、Writer は書き込まず（グループもアドレスも動かさず）、スキップした件数を結果に返す
- [ ] 手動一括登録・当て直しのウィンドウは、スキップがあれば、警告と「読み込み直してください」のメッセージを出す
- [ ] 計画を作った時点と状態が変わっていないエントリは、これまでどおり書き込まれる（手で変えたエントリをルールの内容に戻す動作も変わらない）

### 競合の表示（🟢）
- [ ] 競合の一覧のルール名のボタンは、同じ名前の SO が複数あっても、競合している SO を選ぶ
- [ ] `RegistrationConflict` のルール名とルールの GUID が、同じ並びで持たれる（名前順と GUID 順が逆になる入力でも、対応がずれない）

### パフォーマンス（🔴・🟡）
- [ ] ルールのフォルダの外のインポート（移動元もルールの外のもの）では、AssetDatabase の呼び出しも `CreateEnvironment` も走らない。Resources の配下の警告はこれまでどおり出る
- [ ] Matcher が、パスの判定のたびに文字列を確保しない（`"/" + path`・拡張子の正規化の `Trim`・`ToLowerInvariant` が、判定の経路から無くなる）。判定の結果は変わらない（大文字小文字・ドットの有無・拡張子なし・空の拡張子）
- [ ] ルールの SO の文字列の項目（アドレスのテンプレート・追加先のグループ・拡張子・Label・除外パターン）は、確定（Enter またはフォーカスが外れたとき）してから反映される。打っている途中では、プレビューも Console の警告も更新されない
- [ ] Inspector のプレビューは、対象フォルダが変わったとき・開いたとき・Undo/Redo のときだけアセットを集め直す。それ以外の変更では、集めた結果を使い回す
- [ ] 他のルールとの重なりの警告は、前回と重なりの組が変わったときだけ Console に出る
- [ ] ログの細かさが「まとめだけ」のとき、警告が5件を超えたら Warning が1件にまとまる（件数・最初の5件・「ほか n 件」を含む）。5件以下なら全件出る。「1件ずつ」のときは件数に関係なく全件出る
- [ ] ルール一覧の「当て直す」の差分と警告は、見えている行だけを描く。差分の行の文字列は、`BeginReapply` のときに1回だけ作る
- [ ] 手動一括登録のサムネイルは、プレビューを持たない種類でも、描画のたびにアセットを読み込まない。仮のアイコンは、アセットを読み込まずに出す
- [ ] 手動一括登録の「追加先のグループ」「Label」は、確定してから行を作り直す

### コーディング規則（🟡）
- [ ] `RegistrationGroupRequest`・`RegistrationApplyResult`・`CreateRuleEndNameEditAction` のフィールドが private で、外からは `Acc` のアクセサで触る
- [ ] アクセサの中で関数を呼んでいない（`AccTargetFolderPath`・`RegistrationPlan` の件数4つ・`RegistrationChange` の変更の有無・`RegistrationManualRow.AccCanCheck` を直す）
- [ ] 上の名前の変更に合わせて、既存のテストが追従している

### そのほかの不具合（🟢）
- [ ] Create メニューで名前の入力をキャンセルしたとき、アセットにならなかった SO が残らない
- [ ] 手動一括登録で `{Rule.Name:lower}` のように変換付きで書いても、`{Rule.Name}` と同じ警告が出る
- [ ] 手動一括登録で、登録のあとの読み込みがキャンセルされたとき、キャンセルのメッセージが上書きされない

### 構造・既存機能への影響
- [ ] 変更が Editor アセンブリ（`MAH.AddressableManager.Editor`）と Tests の中だけで完結し、Runtime の型・窓口・`AddressableManager` に触れていない
- [ ] `AddressableAssetSettings` に書き込むのが `RegistrationEntryWriter` だけのまま（ウィンドウから直接書き込まない）
- [ ] Matcher・Expander・PlanBuilder・Formatter が Unity に依存しない形のまま
- [ ] 自動登録・当て直し・手動一括登録の登録結果（アドレス・グループ・Label）が、修正前と同じになる（状態が変わったときのスキップを除く）
- [ ] 開発フォルダだけを変更し、配布フォルダ（ルートの `MAH-AddressableManager/`）には触れていない

### テスト
- [ ] `RegistrationRuleMatcherTests` に、`IsUnderAnyEnabledRuleFolder`（配下・外・無効なルール・移動元）のテストがあり、既存の拡張子のテストも含めてすべて通る
- [ ] `RegistrationPlanBuilderTests` に、競合の名前と GUID の並びがそろうテストがあり、名前の変更に追従した既存のテストとあわせてすべて通る
- [ ] `RegistrationLogFormatterTests` に、警告の要約（6件以上で1件・5件以下で全件・1件ずつでは全件）のテストがあり、`RegistrationConflict` の変更に追従した既存のテストとあわせてすべて通る
- [ ] Writer・Postprocessor・ウィンドウ・Inspector は Unity のアセットと `AddressableAssetSettings` に依存するため、手動の確認（実装計画書の「手動での検証」）で確かめる

## 4. 制約事項

- Editor 拡張は**読み取り専用**が原則で、`Editor/Registration/` だけが例外。書き込みは `RegistrationEntryWriter` の1か所に集め、`Editor/Window/` から書き込まない（CLAUDE.md「API」・仕様書 3.9(7)）
- Runtime の窓口・`AddressableManager` に触れない。機能フォルダの相互参照をしない
- 判定・展開・計画の作成・ログの組み立てに、Unity の型を持ち込まない
- DI コンテナ・R3 に依存しない。UniTask を使わず、同期処理で書く
- 一時コレクションを描画のたびに確保しない。IMGUI で書く（既存の Editor コードと揃える）
- 警告の要約は Formatter だけで行い、PlanBuilder は警告を1件ずつ持つ（既存のテストへの影響を小さくするため）
- 状態の確かめは Writer で行い、「押した時点で計画を作り直す」ことはしない（利用者が確認した差分と違う内容を書かないため）
- 命名は `conventions.md` に従う（フィールド `_camelCase`・アクセサ `Acc`・引数とローカル `snake_case`・定数 `UPPER_SNAKE`）。コメントは日本語で、周りのコードと同じ密度にする
- 仕様書（`asset-registration-spec.md`）は、「ドキュメントの更新に進んで」と指示されるまで書き換えない
- CHANGELOG は更新しない（担当者の運用）。コミットは、指示があるまで行わない
