> 作業ディレクトリ：`.steering/20261024-asset-registration/` ／ 作成日：2026-10-24 ／ ステータス：承認済み ／ 対象 Unity バージョン：6000.3.25f1
> 関連する永続的ドキュメント：`src/AddressableManager/Docs/specs/asset-registration-spec.md`（本機能の仕様の正。実装状況・9章のクラス名は実装後に更新要）／`src/AddressableManager/Docs/addressable-manager-design.md` 3.9(7)・4章（クラス名が変わった場合のみ更新）／`Docs/usage.md` 6章 Editor Tools（「すべて読み取り専用」の記述の修正と登録機能の節の追加が必要）／`src/AddressableManager/Docs/conventions.md`（新しい命名パターンが出たときだけ確認）

## 1. 変更・追加する機能の説明

アセットを Addressables に**登録する** Editor 機能を2つ追加する。判定・マクロの展開・Addressables への書き込みを共通にし、入口だけを分ける。

- **自動登録**：アセットのインポート（AssetPostprocessor）をきっかけに、利用者が作ったルールの SO（`AddressableAutoRegistrationRuleSO`）に従って登録・更新する。ルールの一覧・競合・アドレス重複の確認と、既存アセットへの「当て直す」を行うウィンドウ（`AddressableRegistrationRuleWindow`）を持つ
- **手動一括登録**：Project ウィンドウでフォルダ／アセットを右クリック → 専用ウィンドウ（`AddressableManualRegistrationWindow`）で、グループ・Label・アドレスを決めて一括登録する

背景：Addressables 特有の「登録・グループ分け・アドレス調整」の手作業が多く、登録漏れや git の衝突の原因になるため。プロジェクトの運用方針（パイプライン化したい／登録のタイミングを人が決めたい）に合わせて選べるようにする。本機能は Editor 拡張のうち唯一 `AddressableAssetSettings` に書き込む例外である（CLAUDE.md の API ルール）。

決定済みの仕様（詳細は `specs/asset-registration-spec.md`）：

- 自動登録は既定で有効。Editor SO のスイッチで自動登録だけをオフにできる。ルールの SO は自動で作らず、作った直後は拡張子が空で何も登録しない
- 1つのアセットに2つ以上のルールが当たったら**競合**とし、登録も変更もせずエラー（ルールの SO の組ごとに1件にまとめる）。優先順位で解決しない
- 何度実行しても同じ結果になり、差分がなければ書き込まない。ルールに当たらなくなったアセットは登録を外さず警告する。ルールの SO を変えても自動では当て直さない
- アドレスの重複は、登録はしてエラーを出す。比べる範囲はすべての既存エントリ
- マクロは `{ }`。アセット・フォルダのマクロと標準の値（`{UnityEngine.Application.version}` 等）の決めた一覧だけを展開し、`EvaluateString` は使わない。`:lower` / `:upper` のみ
- 手動一括登録は自動登録のルールに当たるアセットを変更せず、Label は追加だけにする。登録前に確認ダイアログを出す
- **`AddressableAssetSettings` に書き込むのは `RegistrationEntryWriter` の1か所だけ**。`Editor/Window/` からは書き込まない
- 判定・展開・計画・ログ整形は Unity 非依存にして EditMode テストする

## 2. ユーザーストーリー

- アセット管理をパイプライン化したい開発者として、登録の手間をなくすために、ルールを書いておけばインポートのたびに自動で登録されてほしい
- 登録のタイミングを自分で決めたい開発者として、テスト用アセットの混入を防ぐために、フォルダを右クリックして、グループ・Label・アドレスを決めて一括で登録したい
- チームの開発者として、git の衝突を避けるために、同じアセット・同じルールなら誰の環境でも同じ結果になり、差分がなければ書き込まれないでほしい
- ルールを管理する開発者として、意図しない登録を防ぐために、ルールの競合・アドレスの重複を一覧で確認し、ルール変更後は差分を見てから既存アセットに適用したい
- 他の登録ツールを使う開発者として、共存するために、自動登録だけを完全にオフにしたい
- 本モジュールを導入する開発者として、安全に試すために、パッケージを入れただけでは何も変わらないでほしい

## 3. 受け入れ条件

### 設定
- [ ] Editor SO に登録の設定（自動登録スイッチ・ログの細かさ・ルール作成時の初期値（アドレス・Label・除外パターン）・既定の Group Template）が追加され、既存の SO にも既定値が補われる。初期値は仕様 8章のとおり（アドレス `{Asset.Path}`、Label 空、除外 `**/_Test/**` `**/Editor/**`）
- [ ] SO が無いときは `FindRegistrationSettings()` が既定値を返す

### ルールの判定・競合
- [ ] 対象フォルダの配下で、拡張子（大文字小文字・ドットの有無を問わない）に当たるアセットだけがルールに当たる。除外パターン（glob）・除外する拡張子・`Enabled` がオフのルールは当たらない
- [ ] 「拡張子を指定」で拡張子が空のルールは、何も登録せず警告を出す
- [ ] All は、7.2 の「いつも登録しないもの」を除く、登録できるものすべてに当たる
- [ ] パスの範囲と拡張子の**両方**が重なったときだけ競合になる（拡張子が違えば競合しない）。All を特別扱いしない
- [ ] 競合したアセットは、どのルールでも登録・変更されない。Console のエラーは SO の組ごとに1件で、件数と最初の5件のパスが出る
- [ ] ルールの SO の保存時に、他のルールとの重なりが警告される

### マクロ
- [ ] 仕様 6.2 のアセット・フォルダのマクロと 6.3 の標準の値が展開され、`:lower` / `:upper` が効く。マクロ名は大文字小文字を区別する
- [ ] 知らないマクロ・知らない変換は、書かれたままの文字列で登録され、警告が出る（プレビューにも出る）
- [ ] 展開結果が空のとき、アドレスはアセットパス、グループは `DefaultGroup`、Label は付けない。グループ名に使えない文字が入るときは登録せずエラーを出す

### 自動登録（Postprocessor・書き込み）
- [ ] スイッチがオフのとき、何もしない
- [ ] ルールに当たるアセットをインポート・移動・名前の変更すると、ルールのアドレス・グループ・Label で登録・更新される。グループが無ければ作られる（ルールの Group Template、無ければ Editor SO の既定）
- [ ] 同じ入力で再実行しても書き込みが起きない（差分なしは書き込まない）。計画は同じ入力から同じ内容になる
- [ ] 手で別のグループ・アドレス・Label に変えたルール対象のエントリは、次のインポートでルールの内容に戻り、ログに出る
- [ ] ルールに当たらなくなったアセットの登録は外れず、警告が出る。どのルールにも当たらない手動のエントリは触らない
- [ ] アドレスの追従では、登録済みアドレスが変わったときに変更前後が警告に出る。固定では、一度登録したアドレスが変わらない（グループ・Label は当て直される）
- [ ] 同じアドレスが別アセットに付くと、登録はされ、エラーが出る（手動・他ツールのエントリとの重複も対象）
- [ ] ログは設定の細かさ（まとめだけ／1件ずつ）に従う。競合・重複・警告はどちらでも出る
- [ ] `Resources/` 配下・ルール／Editor の SO・`.cs` `.asmdef` `.asmref`・フォルダ・`Packages/` 配下は登録されない（`Resources/` は警告）

### ルールの SO・Inspector
- [ ] Create メニュー（`MAH/Addressable/AutoRegistrationRule`）で作ると、対象フォルダに作った場所が入り、アドレス・Label・除外パターンに Editor SO の初期値がコピーされ、拡張子は空、`Enabled` はオン、追従になる
- [ ] 対象フォルダは GUID で保持され、フォルダの名前の変更で外れない
- [ ] Inspector に、対象数・最初の3件の展開結果・知らないマクロ・拡張子が空・All の注意・競合の警告が出る。プレビューは描画のたびではなく、値の変更時に1回だけ計算される
- [ ] 拡張子の選択は、対象フォルダに実在する拡張子（件数付き）→種類別の定番→手入力の順に出る

### ルールの一覧ウィンドウ
- [ ] メニュー `MAH/Addressable/Auto Registration` で開き、ルール（有効・名前・対象フォルダ・拡張子・グループ・アドレス・対象数）が一覧され、行クリックで SO が選択される。拡張子が空・All の行に印が付く
- [ ] 「作成」で、`Assets/MAH.Data/AddressableManager/Editor/AutoRegistration/` に固定で作られ、同名なら番号が付く
- [ ] 競合とアドレス重複が一覧され、クリックで SO・アセットが選択される
- [ ] 「当て直す」で、差分（追加・グループ移動・アドレス変更・Label 変更）と競合・重複が適用前に一覧され、「適用」で書き込まれる。差分がなければ「変更はありません」と出て書き込まない。キャンセルしたら、そこまでの分が書き込まれた状態で止まる
- [ ] スイッチがオフのとき、「自動登録はオフ」が表示され、「当て直す」が押せず、競合のチェックもしない

### 手動一括登録ウィンドウ
- [ ] フォルダ・アセット（複数可）の右クリックメニューから開く。自動登録のスイッチに関係なく使える
- [ ] 拡張子・グループ（既存／新規＋Template）・Label（既存／新規）・アドレステンプレート・除外・サブフォルダを指定でき、初期値は仕様 5.2 のとおり。`{Root}` は選んだフォルダになり、`{Rule.Name}` は空で警告が出る
- [ ] 各アセットが仕様 5.3 の状態（未登録／登録済み／自動登録／競合中／自動登録の対象（未適用））で表示される。未登録は既定でオン、登録済みは既定でオフ、自動登録・競合中・未適用はチェックできない
- [ ] 「登録する」で確認ダイアログ（登録件数・グループ移動件数・新規グループ／Label・アドレス重複）が出て、OK で登録される。Label は追加だけで、もとの Label は外れない

### 構造・制約
- [ ] `AddressableAssetSettings` に書き込むコードが `RegistrationEntryWriter` の1か所だけである（`Editor/Window/` を含む他のクラスから書き込まない）
- [ ] Matcher・Expander・PlanBuilder・LogFormatter・設定クラスが Unity の型に依存しない
- [ ] Runtime アセンブリ（`AddressableManager`・窓口）に変更がなく、本番ビルドに含まれない
- [ ] 仕様 9.2 のテスト観点を覆う EditMode テストが追加され、既存のテストを含めてすべて通る
- [ ] 一時コレクションを都度確保せず、ルールの SO の探索結果をキャッシュして、インポートのたびに `FindAssets` を呼ばない

## 4. 制約事項

- コードの変更は開発フォルダ `src/AddressableManager/Assets/@MAH/MAH-AddressableManager/` だけで行う（配布フォルダは触らない）
- 全型 `internal`、namespace は `MAH.AddressableManager.Editor.Registration`（設定クラスのみ `...Editor.SettingsSync`）。asmdef は既存の Editor 1つに集約する。命名は `conventions.md` に従う
- UI は既存ウィンドウに合わせて IMGUI、画面の文字は日本語
- VContainer / R3 / DI コンテナに依存しない。UniTask を使う場合は `#if ADDRESSABLE_UNITASK_SUPPORT` の外で `using` しない（本機能では非同期処理を使わない想定）
- 仕様 11.2 の「実装時に確かめること」の結果が仕様と食い違う場合は、黙って実装せず、仕様の更新提案を先に出して承認を得る
- `CHANGELOG.md` は更新しない（担当者の運用）。ドキュメント（仕様書・`Docs/usage.md`）の更新は、実装後に指示を受けてから行う

## 5. スコープ外（今回やらないこと）

- 任意の static プロパティ・Addressables の Profile 変数の評価、日付・連番のマクロ
- Runtime 側の変更・実行時の機能
- 実際の `AddressableAssetSettings` を使う結合テスト（Scanner・Writer・Postprocessor・ウィンドウ・Inspector は手動で確認する）
- `CHANGELOG.md` の更新、レビュー・手動検証の実施（ユーザーの担当）
