# 機能仕様書：アセットの登録（自動登録・手動一括登録）

> 最終更新日：2026-10-24 ／ 対象 Unity バージョン：6000.3.26f1 ／ 対象 Addressables：2.10.3 ／ 実装状況：**実装済み**（2026-10-24。Editor アセンブリ `MAH.AddressableManager.Editor` の `Registration/` と `SettingsSync/`。同日にレビュー指摘を修正：`.steering/20261024-asset-registration-review-fixes/`）
> **Editor 機能7「アセットの登録（自動・手動）」の仕様はこのファイルを正とする**。全体の位置づけは [`addressable-manager-design.md`](../addressable-manager-design.md) 3.9(7)、命名パターンは [`conventions.md`](../conventions.md)、用語は `Docs/glossary.md`（リポジトリルート）が正。
> クラス名・フォルダ配置は、実装で確定した（9章）。改修するときは `conventions.md` のパターンに沿うこと。
>
> 本書は、アセットを Addressables に**登録する**ための2つの Editor 機能（自動登録・手動一括登録）が**どう動くか**を、実装する開発者と、後から改修する開発者が把握するための資料である。Play 中の状態を見るデバッグウィンドウ（[`editor-debug-window-spec.md`](editor-debug-window-spec.md)）・未登録の依存を見る Dependency Check（[`editor-dependency-check-spec.md`](editor-dependency-check-spec.md)）とは違い、**`AddressableAssetSettings` に書き込む**機能である。

## 1. 概要

Addressables 特有の「アセットの登録」「グループ分け」「アドレスの調整」の手間を減らす Editor 機能。プロジェクトの運用方針に合わせて選べるよう、裏側のロジック（ルールの当たり判定・マクロの展開・Addressables への書き込み）を共通にして、2つのきっかけを用意する。

| 機能 | きっかけ | 向いているプロジェクト |
|---|---|---|
| **自動登録** | アセットのインポート（AssetPostprocessor）。利用者が作った**ルールの SO** に従って、裏で登録する | アセット管理をパイプライン化し、登録の手間をなくしたいプロジェクト |
| **手動一括登録** | Project ウィンドウでフォルダを右クリック → 専用ウィンドウで、対象の配下を一覧に出し、拡張子とチェックで絞り込んで、グループ・Label を決めて一括で登録する | テスト用アセットの混入を防ぎたい、登録のタイミングを開発者が決めたいプロジェクト |

| できること | 内容 |
|---|---|
| 自動登録 | ルールの SO（対象フォルダ・拡張子・アドレス・グループ・Label）に当たるアセットを、インポートのたびに登録・更新する（2章） |
| ルールの SO | 何個でも作れる。同じフォルダでも、拡張子が違えば別のルールにできる（3章） |
| ルールの一覧 | すべてのルールの SO・競合・アドレスの重複を一覧し、ルールを既存のアセットに**当て直す**（4章） |
| 手動一括登録 | 選んだフォルダ（またはアセット）の配下を読み込んで一覧に出し、拡張子とチェックで絞り込んで、決めたグループ・Label で登録する（5章） |
| マクロ | アドレス・グループ名・Label を `{Asset.Name}` などから組み立てる（6章） |
| 検証 | ルールの競合・アドレスの重複を知らせる（2.5・7章） |

**この機能が持たないもの**：
- ルールの SO の自動作成（自動登録がオンでも、ルールの SO は必ず利用者が作る。3.3）
- ルールの SO を変えたときの自動の当て直し（4.3 の「当て直す」で行う）
- 登録の解除（ルールに当たらなくなったアセットも、登録を外さない。2.3）
- Dependency Check の結果からの「登録する」ボタン（設計仕様書 5.3。登録はルールの追加か、手動一括登録で行う）
- 任意の static プロパティ・Addressables の Profile の変数の評価（用意したマクロだけを展開する。6.3）
- 実行時（Runtime）の機能。本機能は Editor アセンブリだけで完結し、本番ビルドには含まれない

### 1.1 全体の中での位置づけ

```
Editor アセンブリ（MAH.AddressableManager.Editor）
├─ Window/        … デバッグウィンドウ・Dependency Check（読み取り専用）
├─ Attribute/     … AddressablePath / AddressableLabel のプルダウン
├─ SettingsSync/  … Editor SO（AddressableEditorSettingsSO）と機能ごとの設定
└─ Registration/  … 本書。自動登録・手動一括登録（AddressableAssetSettings に書き込む）
```

- Runtime 側の型・窓口（`IAddressableDebugReader`）・`AddressableManager` には触れない（Runtime のログ出力 `AddressableLogger` だけを使う）
- `AddressableAssetSettings` に書き込むのは、本機能の書き込み担当（9.1 の `RegistrationEntryWriter`）だけにする

### 1.2 自動登録のスイッチ

自動登録は**既定で有効**とし、Editor SO（8章）に**自動登録だけをオフにするスイッチ**を置く。他の登録ツール（サードパーティー製・自作）を使うプロジェクトのためのもの。

| 対象 | スイッチがオンのとき | スイッチがオフのとき |
|---|---|---|
| 自動登録（AssetPostprocessor） | 2章のとおり動く | 何もしない（最初に return する） |
| ルールの SO | 自動登録と、手動一括登録での「自動登録の対象」の判定に使う | **すべて無視する**（手動一括登録でも、自動登録の対象とみなさない） |
| ルールの一覧のウィンドウ | 4章のとおり | 開けるが、上部に「自動登録はオフ」と出す。「当て直す」は押せず、競合のチェックもしない |
| 手動一括登録 | 使える | 使える（手動一括登録にはスイッチを設けない） |

既定で有効にしても、**パッケージを入れただけではグループは変わらない**。ルールの SO は自動で作らず（3.3）、作った直後は拡張子が空で何も登録しない（3.4）ため。

## 2. 自動登録

### 2.1 動くとき・動かないとき

AssetPostprocessor（`OnPostprocessAllAssets`）で、インポートされたアセット・移動されたアセットを受け取る。ウィンドウを開く必要はない。

**次の条件をすべて満たすと動く**：
- Editor SO の自動登録のスイッチがオン
- アセットが追加・インポート・移動・名前の変更をされた（Project ウィンドウへの追加、git の pull、`Library` の再生成による全体の再インポートを含む）
- そのアセットが、`Enabled` のルールの SO の対象フォルダの配下にあり、対象の拡張子に当たる（3.1）

インポートされたアセットのうち、今のパスも移動元のパスも `Enabled` のルールの対象フォルダの外にあるものは、AssetDatabase・Addressables に触る前に、パスの文字列だけで捨てる。スクリプトの保存など、自動登録と関係ないインポートで重い処理（すべてのエントリの走査など）を走らせないため。

**動かないとき**：
- ルールの SO を作ったとき・内容を変えたとき（すでにあるアセットには、4.3 の「当て直す」で適用する）
- Editor SO を変えたとき
- Unity を起動しただけのとき（インポートが走らないため）

### 2.2 1つのアセットの処理の順番

1. いつも登録しないもの（7.2）なら、何もしない
2. `Enabled` のすべてのルールの SO について、当たるかを調べる（3.1）
3. 当たるルールが**0件**：登録済みで、以前はルールに当たっていた場合は警告を出す（2.3）。それ以外は何もしない
4. 当たるルールが**2件以上**：競合（2.5）。登録も変更もしない
5. 当たるルールが**1件**：そのルールのテンプレートを展開し（6章）、アドレス・グループ・Label を決める
6. 今のエントリと比べ、**差分がなければ書き込まない**。差分があれば、登録・グループの移動・アドレスの変更・Label の追加と削除を行う
7. 1回の処理（`OnPostprocessAllAssets` の1回の呼び出し）が終わったら、ログを出す（8章のログの細かさに従う）。競合とアドレスの重複は、まとめてエラーにする（2.5・7.1）。警告は、ログの細かさが「まとめだけ」で5件を超えたら、1件に要約する（8章）

**何度実行しても同じ結果になる**ようにする（同じアセット・同じルールなら、同じアドレス・グループ・Label になる）。チームの別のメンバーが登録したアセットを pull してインポートが走っても、結果が同じなので書き込みが起きず、グループのアセット（`.asset`）が git で衝突しにくくなる。

### 2.3 既存のエントリとの関係

| 状況 | 挙動 |
|---|---|
| どのルールにも当たらないエントリ（手動・他のツールで登録したもの） | **一切触らない** |
| ルールに当たるエントリを、手で別のグループ・アドレス・Label に変えた | 次にそのアセットがインポートされたとき、**ルールの内容に戻し**、ログに出す。例外にしたいアセットは、ルールの除外パターンで外す |
| 移動・名前の変更で、どのルールにも当たらなくなった | **登録を外さず**、警告を出す。外すかどうかは利用者が決める |
| 移動・名前の変更で、別のルールに当たるようになった | 新しいルールで当て直す |
| 削除された | 何もしない（Addressables 側でエントリが外れる） |

Label は、ルールが付ける Label に合わせて追加・削除する。ルールが管理しない Label（手で付けたもの）を区別する仕組みは持たないため、ルールに当たるアセットの Label は、ルールの内容がすべてになる。

### 2.4 アドレスの追従と固定

`{Path.Relative}` などパスを使ったアドレスは、アセットの移動・名前の変更で変わる。コードや SO に書いたアドレスの文字列が壊れるため、ルールの SO ごとに選べるようにする。

| 設定 | 挙動 |
|---|---|
| 追従（既定） | 移動・名前の変更のたびに、アドレスを展開し直す。**登録済みのアドレスが変わったときは、変更前と変更後を警告に出す**（数が多いときは要約される。8章） |
| 固定 | 一度登録したら、アドレスを変えない（グループ・Label は当て直す）。新しく登録するときだけ展開する |

アドレスが変わらない形にしたいときは、`{Asset.Guid}`（6.2）を使う方法もある（そのかわり、人には読めないアドレスになる）。

### 2.5 ルールの競合

**定義**：1つのアセットが、2つ以上のルールの SO に当たること。パスの範囲と拡張子の**両方**が重なったときだけ起きる。

| 対象フォルダ | 拡張子 | 結果 |
|---|---|---|
| `Samples/AddressableDownload` | `.prefab` | 当たる |
| `Samples/AddressableDownload` | `.mat` | 当たる（拡張子が違うので競合しない） |
| `Samples/AddressableDownload` | `.png` | 当たる |
| `Samples/AddressableInitialize` | 任意 | 当たる（パスが違うので競合しない） |
| `Samples/`（親のフォルダ） | `.prefab` | **競合**（`AddressableDownload` の中の prefab が1行目と重なる） |

- 入れ子のフォルダを指定すること自体はエラーにしない。内側のアセットが両方に当たったときだけ競合になる。入れ子にしたいときは、外側のルールの除外パターンで内側を外す
- All（3.2）を特別扱いして優先させない。All のルールと `.png` のルールが同じフォルダにあれば、`.png` が競合する。`.png` を別にしたいときは、All の側で `.png` を除外する（規則を「重なったら競合」の1つにするため）
- **競合したアセットは、どのルールでも登録・変更しない**（どちらかを勝手に選ばず、今の状態を保つ）
- Console に**エラー**を出す。アセットごとに出すと Console があふれるため、1回の処理の中で**ルールの SO の組ごとに1件**にまとめ、件数と最初の数件（5件）のパスを出す
- ルールの SO を保存したとき（`OnValidate`）にも、他のルールの SO との重なり（対象フォルダの包含と拡張子の重なり）を調べ、競合しそうなら**警告**を出す
- 競合は、ルールの一覧のウィンドウ（4.2）にも溜めて表示する

## 3. ルールの SO（`AddressableAutoRegistrationRuleSO`）

1つの SO に、**対象フォルダ1つ**のルールを書く。何個でも作れて、それぞれが自動登録を行う。型（`AssetDatabase.FindAssets("t:AddressableAutoRegistrationRuleSO")`）で探すため、置き場所は自由。

ルールの SO は、利用者が何個でも作る**データ**であり、プロジェクトに1つずつの設定 SO（Runtime SO・Editor SO）とは性質が違う。そのため、「機能ごとに設定 SO を分けない」方針（設計仕様書 3.1.1）の対象外とする。

### 3.1 項目

| 項目 | 内容 |
|---|---|
| `Enabled` | この SO だけをオフにする（一時的に止めたいとき）。オフの SO は、自動登録・競合の判定・手動一括登録での「自動登録の対象」の判定のすべてで、無いものとして扱う |
| 対象フォルダ | フォルダのアセットをドラッグして指定する。**GUID で持つ**（フォルダの名前の変更や、`Samples~` を Import したときのパスの変化で外れないようにするため）。`Assets/` の中のフォルダに限る |
| 対象の指定方法 | 「拡張子を指定」か「All」（3.2） |
| 拡張子 | 対象にする拡張子（複数）。「拡張子を指定」のとき使う |
| 除外する拡張子 | 「All」のとき使う |
| 除外パターン | glob（例：`**/_Test/**`）。対象フォルダの配下でも、当たるものは対象にしない |
| アドレスのテンプレート | マクロ（6章）を使える。空ならアセットパス（3.5） |
| 追加先のグループ（Inspector の項目名は Target Group） | 追加先のグループの名前を**直接**書く。マクロを使える。空なら Addressables の `DefaultGroup`（3.5）。既存のグループから、プルダウン（「グループを選ぶ ▼」）でも選べる。Built In Data など読み取り専用のグループは出さない |
| 新規グループの Template（Inspector の項目名は Group Template Asset） | 追加先のグループが無いときに、新しく作るのに使う Addressables の Group Template（SO の参照）。空なら Editor SO の既定の Group Template（8章） |
| Label | 複数。マクロを使える。空なら Label を付けない。既存の Label から、プルダウン（「Label を選ぶ ▼」）でも選べる（選ぶたびに追加／解除が切り替わる）。マクロ入りの Label や、まだ無い Label は、手入力の欄で足す |
| アドレスの追従／固定 | 2.4。既定は追従 |

**拡張子の扱い**：
- 大文字と小文字を区別しない。`.png` と `png` を同じ扱いにする
- 「拡張子を指定」で拡張子が空：**何も登録せず、警告を出す**（Inspector とルールの一覧のウィンドウ）。うっかり全部を登録する事故を防ぐため

**拡張子の選び方**：既存の `AddressablePathDropdown` と同じ `AdvancedDropdown`（検索ボックス付き）で、複数を選ぶ。候補の並びは次のとおり。
1. **対象フォルダに実際にある拡張子**（いちばん上。数も添える）。何があるかを見ながら選べ、登録漏れに気づきやすくするため
2. よく使う拡張子を種類別に：Prefab（`.prefab`）・Scene（`.unity`）・Material（`.mat`）・Texture（`.png` `.jpg` `.psd` `.tga` `.exr`）・Audio（`.wav` `.mp3` `.ogg`）・Model（`.fbx` `.obj`）・Animation（`.anim` `.controller`）・ScriptableObject（`.asset`）・Font（`.ttf` `.otf`）・Text（`.txt` `.json` `.bytes`）・Shader（`.shader`）・Video（`.mp4`）・SpriteAtlas（`.spriteatlas`）
3. 一覧にないものは**手入力で追加**できる（AdvancedDropdown の中には入力欄を置けないため、ドロップダウンの外の入力欄で足す）

選ぶたびにドロップダウンが閉じ、選んだ拡張子の追加／解除が切り替わる（選択済みにはチェックの印）。複数を選ぶときは、開き直す。

### 3.2 All（登録できるものはすべて）

対象フォルダの配下で、**Addressables に登録できるものはすべて**登録する。特別な文字列（`*` など）を拡張子の欄に書く形にせず、「対象の指定方法」の選択肢にする（書き間違いや、他の拡張子と混ぜたときの扱いがあいまいになるため）。

- 「除外する拡張子」で、一部の拡張子を外せる
- いつも登録しないもの（7.2）は、All でも登録しない
- **注意**：Prefab が使っているテクスチャ・マテリアルまで、すべて個別のエントリになる。本来は Prefab のバンドルに暗黙的に同梱されるだけだったものが独立したエントリになり、バンドルの構成が変わる。Inspector とルールの一覧のウィンドウに、この注意を表示する

### 3.3 作り方

**ルールの SO は自動では作らない**。自動登録のスイッチがオンでも、必ず利用者が作る（Editor SO はエディターの起動時に自動で作るが、それとは扱いが違う）。作り方は2つ。

| 作り方 | 作る場所 | 対象フォルダの初期値 |
|---|---|---|
| ルールの一覧のウィンドウ（4.1）の「作成」 | `Assets/MAH.Data/AddressableManager/Editor/AutoRegistration/` に**固定**。ファイル名だけを入力し、同じ名前があれば番号を付けてずらす（`AssetDatabase.GenerateUniqueAssetPath`）。保存先を選ぶダイアログは出さない（`MAH.Data` の外に置けてしまうため） | 空 |
| Create メニュー（Project の右クリック → Create → `MAH/Addressable/AutoRegistrationRule`） | 右クリックした場所 | **作った場所のフォルダ**（そのフォルダを対象にすることが多いため） |

Create メニューは `CreateAssetMenu` ではなく、**独自の `MenuItem`（`RegistrationRuleAssetCreator`）で作る**。`ScriptableObject.Reset` が `CreateAssetMenu` からの作成で呼ばれるかに頼らず、作成のたびに確実に Editor SO の初期値をコピーし、対象フォルダの初期値に作った場所を入れるため（名前の入力が終わった時点で、`EndNameEditAction` が初期化してアセットを作る。11.2）。

ルールの SO を対象フォルダの中に置く使い方（例：`Samples/AddressableDownload/` に `.prefab` 用・`.mat` 用・`.png` 用の3つを置く）は、Create メニューの作り方になる。

### 3.4 作った直後の状態

| 項目 | 作った直後 |
|---|---|
| `Enabled` | オン |
| 対象の指定方法 | 拡張子を指定 |
| 拡張子 | **空**（何も登録されず、警告だけが出る。拡張子を選んだ時点で動き始める） |
| アドレスのテンプレート・Label・除外パターン | Editor SO の「**ルールの作成時の初期値**」（8章）を**コピー**する |
| その他 | 空（追加先のグループ・新規グループの Template）、追従 |

- コピーしたあとは、ルールの SO と Editor SO は**無関係**になる。ルールの SO は自由に書き換えてよく、あとで Editor SO の初期値を変えても、すでにあるルールの SO には反映しない
- 初期値は「毎回同じ値を書く手間を省く」ためのもので、評価のときに Editor SO の値を参照する仕組み（既定値の継承・足し合わせ）は持たない
- 作っただけでは登録は走らない（2.1）。すでにあるアセットには、拡張子を選んだあとで「当て直す」（4.3）で適用する

### 3.5 項目を空にしたとき

| 項目 | 空のとき |
|---|---|
| 拡張子（拡張子を指定） | 何も登録せず、警告 |
| アドレスのテンプレート | **アセットパス**で登録する（Addressables に普通に登録したときと同じアドレスで、必ず一意になる）。欄には「空の場合：アセットパス」と薄く表示する |
| 追加先のグループ | Addressables の `DefaultGroup` |
| Label | Label を付けない |

- 空のときに使う値は**決まった値**で、Editor SO の初期値は使わない（コピーしたあとは無関係、という 3.4 の決まりを崩さないため）
- `DefaultGroup` は、名前（「Default Local Group」）では探さず、`AddressableAssetSettings.DefaultGroup` を使う。Groups ウィンドウで名前を変えたり、別のグループを「Set as Default」にしたりしても外れないため。既定のグループを変えたいときは、Addressables 側で Set as Default にする（**ルールの SO は既定のグループを持たない**。手動一括登録だけは、追加先のグループを決めなかったときのために、Editor SO の「既定の追加先グループ」を持つ。5.2・8章）

### 3.6 Inspector のプレビュー

ルールの SO の Inspector（CustomEditor）の下に、**読み取り専用**で展開の結果を表示する。

- 対象のアセットの数と、例として**最初の3件**の展開結果（アドレス・グループ・Label）
- 知らないマクロ（6.5）・拡張子が空・All の注意・ほかのルールとの重なり（競合しそうか。2.5）・対象フォルダが未指定・ルールが無効（`Enabled` がオフ）の警告
- Inspector には、拡張子の選択（3.1。「拡張子を選ぶ ▼」と手入力の欄）、Label の選択（「Label を選ぶ ▼」と手入力の欄）、追加先のグループの選択（「グループを選ぶ ▼」）のボタンがある。対象の指定方法が「拡張子を指定」のときは拡張子の欄、「All」のときは除外する拡張子の欄を出す
- 他のルールとの重なりは、ルールの SO を**選択して編集しているときだけ** Console にも警告する（`OnValidate` は読み込みのたびにも呼ばれ、そのたびに出すと多すぎるため。2.5 の「保存時」の実装）。重なっている相手の組が**前回と変わったときだけ**出す（重なりに関係ない項目を編集するたびに、同じ警告が出ないようにするため）
- 文字列の項目（アドレスのテンプレート・追加先のグループ・拡張子・Label・除外パターン）は、**Enter を押すかフォーカスが外れたときに確定**し、そのときにプレビューへ反映する（`[Delayed]`）。1文字打つたびに `OnValidate`・プレビューの計算・重なりの警告が走らないようにするため
- 対象のアセットを探す処理は重いため、**描画のたびには行わない**。対象フォルダのアセットの一覧と Addressables 側の状態は、対象フォルダが変わったとき・Inspector を開いたとき・Undo/Redo のとき・プロジェクトが変わったとき（`EditorApplication.projectChanged`）だけ集め直す。それ以外の値の変更では、集めた結果を使って展開だけをやり直す。プロジェクトが大きくても Inspector が重くならないようにするため

## 4. ルールの一覧のウィンドウ（`AddressableRegistrationRuleWindow`）

ルールの SO はプロジェクトのあちこちに置けるため、どの SO がどのフォルダ・拡張子を受け持っているかを一覧で確かめるウィンドウを持つ。Console のエラーは流れて見逃されるため、競合とアドレスの重複もここに溜める（リーク検出一覧と同じ理由）。

- **自動登録に必須ではない**（自動登録はウィンドウを開かなくても動く）
- ルールの**編集はしない**（SO の Inspector で行う）。できるのは、見ること・ルールの SO の作成（3.3）・当て直すこと
- 手動一括登録の画面はここに入れない（5章の専用ウィンドウ）
- メニューは `MAH/Addressable/Auto Registration`。画面の文言は `EditorText` から取り、表示言語（日本語・英語・利用者が足した言語）に従う（[`editor-localization-spec.md`](editor-localization-spec.md)）

### 4.1 ルールの一覧

| 列 | 内容 |
|---|---|
| 有効 | `Enabled` |
| ルール | SO の名前 |
| 対象フォルダ | パス |
| 拡張子 | 拡張子の一覧、または「All（除外：…）」 |
| グループ | 追加先のグループ |
| アドレス | アドレスのテンプレート |
| 対象の数 | 当たっているアセットの数 |

- 行をクリックすると、その SO を選択する（`Selection.activeObject`・`EditorGUIUtility.PingObject`）
- 拡張子が空・All の注意は、行に印を付ける
- 「作成」ボタンで、ルールの SO を作る（3.3）
- 一覧は、ウィンドウを開いたとき・「再読み込み」ボタン・ルールの SO の追加と削除のときに作り直す。ルールの SO の値を変えただけのときは、全体を集め直すと重いため、自動では作り直さず、「古い可能性があります」と知らせて再読み込みを促す

### 4.2 競合とアドレスの重複

- **ルールの競合**（2.5）：競合しているルールの SO の組と、対象のアセット
- **アドレスの重複**（7.1）：同じアドレスを持つアセットと、そのグループ
- どちらも、クリックで SO・アセットを選択できる。ルールの SO は GUID で選ぶ（別のフォルダに同じ名前の SO があっても取り違えないため）
- エラー・警告・当て直しの差分（4.3）は、件数が多くても重くならないよう、**見えている行だけを描く**一覧にする。1行に収め、全文はツールチップに出す

### 4.3 当て直す

ルールの SO を作ったり変えたりしたあと、**すでにあるアセットにルールを適用する**操作。ルールの SO の変更では自動で当て直さないため（2.1）、この操作で行う。

1. 「当て直す」を押すと、すべての `Enabled` のルールについて、対象フォルダの配下のアセットを集め、2.2 の 1〜5 で結果を求める（まだ書き込まない）
2. **差分を一覧で見せる**：追加・グループの移動・アドレスの変更・Label の変更。あわせて、競合とアドレスの重複も出す
3. 利用者が確認して「適用」を押すと、書き込む（キャンセルできる進捗バー付き。キャンセルしたら、そこまでの分は書き込まれた状態で止まる）。差分を求めた時点から**状態が変わっていたエントリ**（その間に、別の操作で登録・グループの移動・アドレスの変更をされたもの）は、書き込まずに**スキップ**し、件数を知らせる。見せた差分と違う内容を書かないため
4. 結果をログに出す

- 自動登録のスイッチがオフのときは押せない（1.2）
- 差分がなければ「変更はありません」と出して、書き込まない

## 5. 手動一括登録（`AddressableManualRegistrationWindow`）

ルールの SO を使わず、**選んだフォルダ・アセットの配下を読み込んで一覧に出し、拡張子とチェックで絞り込んで、決めたグループ・Label で一括で登録する**。設定を先に決めてから読み込むのではなく、**先に全部読み込んで、不要なものを外していく**流れにして、画面の設定項目を減らしている（2026-10-24）。

### 5.1 入口

- Project ウィンドウで**フォルダ**を選び、右クリックメニュー → `MAH` → `Register to Addressables...`（メニューの項目は `Assets/MAH/Register to Addressables...`）→ 専用ウィンドウが開く
- 右クリックメニューは「MAH → コマンド」の1階層にする。並び順の数字（priority）を他の項目から大きく離し（10000）、Unity が入れる区切り線で、他のパッケージのコマンドと区画を分ける。区切りの位置は数字の離れ具合で決まるため、完全には指定できない
- **アセット**を選んで右クリックしたときもメニューを出し、選んだアセットだけを対象にする（拡張子では絞らない）
- **複数のフォルダ**（アセット）を選んだときは、まとめて1つのウィンドウに出す。同じアセットは1行にする
- 自動登録のスイッチに関係なく、いつでも使える

### 5.2 画面

流れは次の4ステップ。

1. **読み込んで一覧を表示**：開いた時点で、対象の配下をすべて読み込んで一覧に出す。未登録のものは最初からチェックオン
2. **拡張子で絞り込む**：対象に実在する拡張子が、件数つきで並ぶ。最初はすべてオン。拡張子ごとにオン／オフを切り替えると、その拡張子の行が一覧から消える。行ごとのチェックでも、個別に外せる
3. **追加先のグループ・Label を決める**：決めなければ、Editor SO の設定が最初から入っている
4. **登録する**：確認のダイアログ（5.4）のあと、登録する

```
[対象]            Assets/.../AddressableDownload   ☑ サブフォルダを含む
[拡張子で絞り込む]  ☑ .prefab (12)  ☑ .png (30)  ☐ .mat (4)      [すべてオン][すべてオフ]
[対象のアセット（N 件）]
  ☑ [絵]  Assets/.../Title.prefab
          未登録   → Download/Title
  ☑ [絵]  Assets/.../Icon.png
          未登録   → Download/Icon
─────────────────────────────  ここから下は、画面を小さくしても常に見える
[各種設定]        追加先のグループ [                ] [グループを選ぶ ▼]
                  Label            （リスト）         [Label を選ぶ ▼] [手入力][追加]
  [すべて選ぶ] [すべて外す]                         [登録する（N 件）]
```

| 項目 | 初期値 | 内容 |
|---|---|---|
| 対象 | 選んだフォルダ・アセット | サブフォルダを含むかを選べる（既定は含む）。切り替えると読み込み直す |
| 拡張子で絞り込む | すべてオン | 件数つきの一覧（一覧に出るアセットだけで数える）。拡張子のないものは「（拡張子なし）」。アセットを直接選んだ場合は、拡張子では絞らない |
| 追加先のグループ | Editor SO の「既定の追加先グループ」（8章）。空なら Addressables の `DefaultGroup` | 既存のグループからプルダウンで選ぶか、名前を直接書く（マクロを使える）。同じ名前のグループが無ければ、登録のときに新しく作る。直接書いたときは、Enter かフォーカスが外れたときに確定し、一覧を作り直す（1文字ごとに全行を作り直さないため） |
| Label | Editor SO の「ルールの作成時の初期値」の Label | 既存の Label からプルダウンで選ぶか、直接書く（マクロを使える）。直接書いたときの確定は、追加先のグループと同じ |
| アセットの一覧 | — | 1行に1アセット（サムネイル・パス・状態・展開したアドレス）。チェックを入れたものだけを登録する |

**画面に出さない項目**（Editor SO の値を、そのまま使う）：

- アドレスのテンプレート：Editor SO の「ルールの作成時の初期値」のアドレス。変えたいときは Editor SO を変える
- 除外パターン：Editor SO の「ルールの作成時の初期値」の除外パターン
- 新規グループの Template：Editor SO の「既定の Group Template」

**一覧の見え方**：

- 1行は2段。上段はパス（クリックで Project ウィンドウに表示）、下段は状態と `→ アドレス`（展開に失敗したときは `! エラー内容`）。サムネイルは、見えている行の分だけ読み込む。プレビューを持たない種類（`.asset`・`.anim` など）は、種類のアイコンを覚えておき、描画のたびにアセットを読み込み直さない
- 大量のアセットでも重くならないよう、**見えている行だけを描く**（行の高さを固定する）
- 拡張子の一覧と、アセットの一覧の高さは、ウィンドウの高さの割合で決まる（ウィンドウを大きくすると大きくなる。アセットの一覧は、少なくとも6行が見える）
- 「対象」「拡張子」「対象のアセット」は、外側のスクロールに入る。「各種設定」と下のボタンは、スクロールの外に固定し、ウィンドウが小さくてもボタンが隠れない。各区画は枠（Box）で囲む

**マクロ**：

- `{Root}` は**右クリックで選んだフォルダ**（アセットを直接選んだときは、そのアセットを含むフォルダ）になる
- `{Rule.Name}` はルールの SO がないため**空**として扱い（6.5 の空のときの扱いに従う）、画面に警告を出す（`{Rule.Name:lower}` のように変換を付けた書き方でも出す）

画面の文言は `EditorText` から取り、表示言語に従う（日本語・英語・利用者が足した言語。[`editor-localization-spec.md`](editor-localization-spec.md)）。

### 5.3 アセットの状態と扱い

**すでに登録済みのアセットは、一覧に出さない**。手動・他のツールで登録したものも、自動登録で登録したものも同じで、出さなかった件数だけ「登録済みの N 件は表示していません」と知らせる。一覧に出るのは未登録のものだけ。

| 状態 | 表示 | チェック |
|---|---|---|
| 未登録 | 「未登録」 | 既定でオン |
| 自動登録のルールが競合していて、未登録 | 「競合中」 | できない。競合を先に直す |
| 自動登録のルールに当たるが、まだ当て直していない（未登録） | 「自動登録の対象（未適用）」 | できない。ルールの一覧のウィンドウで当て直す |
| いつも登録しないもの（7.2） | 表示しない | — |

- 自動登録のルールに当たるアセットを変更しないのは、自動登録で登録済みであり、手動で別のグループに入れても、次のインポートでルールの内容に戻されるため（2.3）
- 競合中・未適用のアセットも手動で登録させない。手動で登録すると、競合を直したとき・当て直したときに、結果がルールの内容と食い違うため
- ルールの SO の `Enabled` がオフのとき、または自動登録のスイッチがオフのときは、自動登録の対象とみなさず、手動で登録できる
- **Label は追加だけ**にする。もとから付いている Label は外さない（他の用途で付けた Label を消さないため）
- 内部の計画作成（`RegistrationPlanBuilder`）は、登録済みのアセットのグループの移動・アドレスの書き換えにも対応しているが、画面では使わない（登録済みを一覧に出さないため）

### 5.4 登録の前の確認

「登録する」を押すと、確認のダイアログを出す。Addressables のグループの変更は Undo で戻しにくいため。

- 内容：「N 件を登録し、M 件のグループを移動します」と、新しく作るグループ・Label
- アドレスの重複（7.1）があれば、ここで知らせ、そのまま登録するかを選ばせる
- 書き込む時点で、一覧を作った時点から**状態が変わっていたアセット**（ウィンドウを開いている間に、別の操作で登録されたものなど）は、書き込まずに**スキップ**し、件数を知らせる。確認した内容と違うグループ・アドレスに書き換えないため（4.3 と同じ）
- 登録が終わったら、結果をログに出し、一覧を作り直す。作り直しの読み込みをキャンセルしたときは、書き込みの結果とキャンセルの両方を画面に残す

## 6. マクロ

### 6.1 書き方と使える欄

- 記号は `{ }`。例：`{Folder.Top}/{Asset.Name}`
- 使える欄：アドレス・グループ名・Label の3つ
- 展開の処理は、自動登録・当て直し・手動一括登録・Inspector のプレビューで**共通**（9.1 の `RegistrationMacroExpander`）
- マクロの名前は**大文字と小文字を区別する**（`{asset.name}` は知らないマクロとして扱う）
- 値は**登録したときに固定**される。あとで値が変わっても、当て直すまでアドレス等は変わらない

### 6.2 アセット・フォルダのマクロ

例は `Assets/App/Audio/BGM/Title.wav`、ルールの対象フォルダは `Assets/App` とする。

| マクロ | 内容 | 例 |
|---|---|---|
| `{Asset.Path}` | アセットパス（拡張子付き） | `Assets/App/Audio/BGM/Title.wav` |
| `{Asset.Name}` | 拡張子を除いたファイル名 | `Title` |
| `{Asset.Extension}` | 拡張子（ドットなし） | `wav` |
| `{Asset.Type}` | メインアセットの型名（`AssetDatabase.GetMainAssetTypeAtPath`）。`.png` は Sprite として使っていても `Texture2D` になる | `AudioClip` |
| `{Asset.Guid}` | アセットの GUID。移動しても名前を変えても変わらない | `3f2a…` |
| `{Folder.Name}` | 直属の親フォルダの名前 | `BGM` |
| `{Folder.Top}` | 対象フォルダの直下のフォルダの名前 | `Audio` |
| `{Folder.Relative}` | 対象フォルダから親フォルダまでのパス | `Audio/BGM` |
| `{Root}` | ルールの対象フォルダ（手動一括登録では、選んだフォルダ） | `Assets/App` |
| `{Path.Relative}` | 対象フォルダからの相対パス（拡張子なし） | `Audio/BGM/Title` |
| `{Rule.Name}` | ルールの SO の名前（手動一括登録では空） | `BGM_Rule` |

### 6.3 標準の値のマクロ

よく使いそうな Unity の値だけを、**標準の書き方（フルネーム）のまま**独自のマクロとして用意する。Addressables の Profile や公式のドキュメントで見かける書き方なので、利用者がそのまま書ける。

| マクロ | 中身 | 例 | 環境によって値が変わるか |
|---|---|---|---|
| `{UnityEngine.Application.version}` | Player Settings の Version | `1.2.0` | 変わらない |
| `{UnityEngine.Application.productName}` | Product Name | `MyGame` | 変わらない |
| `{UnityEngine.Application.companyName}` | Company Name | `MAH` | 変わらない |
| `{UnityEngine.Application.identifier}` | Bundle Identifier | `com.mah.mygame` | プラットフォームによっては変わる |
| `{UnityEngine.Application.unityVersion}` | Editor のバージョン | `6000.3.25f1` | 変わり得る（Editor のバージョンがそろっていない場合） |
| `{UnityEngine.Application.platform}` | 実行中のプラットフォーム | `WindowsEditor` | 変わる（エディタの OS による） |
| `{UnityEditor.PlayerSettings.bundleVersion}` | Player Settings の Version（エディタでは `Application.version` と同じ値） | `1.2.0` | 変わらない |
| `{UnityEditor.EditorUserBuildSettings.activeBuildTarget}` | 選んでいるビルドターゲット | `Android` | 変わる |

- 任意の static プロパティや、Addressables の Profile の変数（`[BuildTarget]` など）は**評価しない**。Addressables の評価処理（`EvaluateString`）に任せない理由は 10章。必要な値は、要望を受けて上の一覧に追加する
- 環境によって値が変わるものも使える。ただし、メンバーごとに値が違うと、インポートのたびに互いのアドレスを書き換え合う（2.2 の「何度実行しても同じ結果」が崩れる）。Inspector では警告を出さず（分かって使う前提）、利用者向けの説明（`Docs/usage.md`）の一覧に「環境によって値が変わるか」の列を載せる
- `{UnityEngine.Application.version}` をアドレスに使うと、バージョンを上げて当て直したときにアドレスが変わる

### 6.4 大文字・小文字の変換

- `{マクロ:lower}`（小文字）と `{マクロ:upper}`（大文字）の2つだけ。例：`{Asset.Name:lower}` → `title`
- すべてのマクロ（標準の値を含む）に付けられる

### 6.5 展開できないとき

| 状況 | 扱い |
|---|---|
| 知らないマクロの名前（例：`{Asset.Nmae}`）・知らない変換（例：`{Asset.Name:camel}`） | **書かれたままの文字列で登録し、警告を出す**。Inspector のプレビューにも出す |
| 展開した結果が空（例：対象フォルダの直下のアセットで `{Folder.Top}` を使った、手動一括登録の `{Rule.Name}`） | アドレス → アセットパス／グループ → `DefaultGroup`／Label → 付けない（3.5 と同じ） |
| グループ名に使えない文字が入る（例：`{Path.Relative}` の `/`） | 登録せず、エラーを出す（使えない文字の判定は OS に依存する。既知の制約。11.2） |

**入れないマクロ**：日付・時刻・連番など、実行するたびに値が変わるもの。「何度実行しても同じ結果になる」（2.2）と食い違うため。

## 7. 検証といつも登録しないもの

### 7.1 アドレスの重複

別々のアセットに、同じアドレスが付くこと（例：アドレスを `{Asset.Name}` にして、別々のフォルダに `Icon.png` がある）。Addressables 自体は重複を許すが、本モジュールの `LoadAsync`（Path 入口）ではどちらが読まれるか分からなくなる。

| 状況 | 扱い |
|---|---|
| 自動登録・当て直しで重複する | **登録はして、エラーを出す**（どちらのアセットも、登録すること自体は正しいため。競合とは違い、登録を止めない）。ルールの一覧のウィンドウ（4.2）にも出す |
| 手動一括登録で重複する | 登録の前の確認のダイアログで知らせ、そのまま登録するかを選ばせる（5.4） |

- 比べる範囲は、本機能で登録したものだけでなく、**すでにあるすべてのエントリ**（手動・他のツールで登録したものとの重複も、同じく問題になるため）
- 同じアセットを別の型で読むこと（`Texture2D` と `Sprite`）は、同じアセットなので重複ではない

### 7.2 いつも登録しないもの

ルールの SO・手動一括登録の設定に関係なく、次のものは登録しない（All でも登録しない）。

| 対象 | 理由 |
|---|---|
| ルールの SO・Editor SO 自体 | `.asset` を対象にしたルールの配下にルールの SO を置くと、SO が自分自身を登録してしまうため |
| `.cs`・`.asmdef`・`.asmref`・`.meta` | スクリプト・アセンブリの定義はバンドルに入らない。`.meta` はアセットとして扱われないが、明記しておく |
| フォルダ | 本機能はアセット1つずつ登録し、フォルダエントリは作らない（アドレス・Label をアセットごとに決めるため） |
| `Resources/` の配下 | Addressables に登録すると、Resources とあわせてビルドに二重に入るため。**登録せず、警告を出す** |
| `Packages/` の配下 | 対象フォルダは `Assets/` の中に限る |
| Addressables が受け付けないもの | Addressables 自体が登録を拒む拡張子（`.cs` `.js` `.boo` `.exe` `.dll` `.meta` `.preset` `.asmdef`。本機能は `.asmref` も除く）、`Editor/` の配下、Addressables の設定フォルダ（`ConfigFolder`）。Addressables の判定処理は `internal` で呼べないため、同じ条件を自前で持つ（`RegistrationRuleMatcher`。11.2） |

## 8. 設定項目（`AddressableRegistrationSettings`）

`AddressableEditorSettingsSO`（[`editor-debug-window-spec.md`](editor-debug-window-spec.md) 3章）が保持する `[Serializable]` クラス。

| 項目 | 既定 | 内容 |
|---|---|---|
| 自動登録 | オン | 自動登録だけのオン／オフ（1.2）。手動一括登録には影響しない |
| ログの細かさ | まとめだけ | 「まとめだけ」（1回の処理で N 件登録・M 件変更）／「1件ずつ」（アセットごとに出す）。競合・アドレスの重複・エラーは、どちらでも全件出す。警告は、「まとめだけ」のときは5件を超えたら1件に要約し（件数・最初の5件・ほかの件数）、「1件ずつ」のときは全件出す |
| ルールの作成時の初期値：アドレスのテンプレート | `{Asset.Path}` | ルールの SO を作るときにコピーする値（3.4）。手動一括登録では、画面に出さず、この値をそのまま使う |
| ルールの作成時の初期値：Label | 空 | 同上。手動一括登録の画面の Label の初期値にもなる |
| ルールの作成時の初期値：除外パターン | `**/_Test/**`、`**/Editor/**` | 同上。テスト用のアセットと、Editor フォルダのものを混ぜないため。手動一括登録でも、この値をそのまま使う |
| 既定の追加先グループ（Default Target Group） | 空（Addressables の `DefaultGroup`） | **手動一括登録だけ**で使う。追加先のグループを決めなかったとき（画面の初期値）に入れるグループの名前。ルールの SO（自動登録）では使わない（3.5） |
| 既定の Group Template | 空（Addressables の既定の Template） | 追加先のグループが無いときに、新しく作るのに使う。ルールの SO で指定すれば、そちらを使う。手動一括登録では、これを使う |

- 「ルールの作成時の初期値」は、作るときにだけ使う値で、評価のときには参照しない（3.4）。項目名でも「作成時の初期値」と分かるようにする（既定値と混同しないため）
- アドレスの初期値を `{Asset.Path}` にするのは、必ず一意で、Addressables に普通に登録したときと同じアドレスになるため。`{Path.Relative}` を初期値にすると、別のルールの同じ名前のアセット（`Assets/UI/Icon.png` と `Assets/Item/Icon.png`）が同じアドレスになりやすい
- Label の初期値を空にするのは、固定の Label を入れておくと、Label を指定しなかったルールのアセットがすべて同じ Label にまとまり、`LoadByLabelAsync`・`DownloadAsync` で意図しないものまで対象になるため
- 取得は `AddressableEditorSettingsLocator.FindRegistrationSettings()`。SO が無いときは既定値を使う
- 既存の Editor SO には、追加した項目だけコードの初期値が入る（保存されていない項目は、フィールドの初期値になるため）。`OnValidate` で `null` を補う（既存の設定クラスと同じ）。Inspector の Reset で既定に戻る

## 10. 設計の判断と理由

- **自動登録を既定で有効にし、スイッチで自動登録だけをオフにできるようにする**：自動登録を作って使う人が多いため、既定で使える状態にする。一方、公開パッケージとして、他の登録ツールと共存できるよう、完全にオフにする手段を持つ。手動一括登録は利用者が明示的に操作するものなので、スイッチを設けない
- **既定で有効でも、入れただけでは何も起きないようにする**：ルールの SO を自動で作らず、作った直後は拡張子が空で何も登録しない。パッケージを入れた時点で利用者のグループが書き換わると、公開パッケージとして問題になるため
- **ルールの SO を1つのフォルダ・1つのルールにし、何個でも作れるようにする**：競合のエラーで「どの SO とどの SO か」を示せ、SO ごとのオン／オフもしやすいため。1つの SO にルールのリストを持たせると、競合の単位が「SO の中の何番目」になって分かりにくくなる
- **競合したら優先順位で決めず、エラーにして登録しない**：リストの順や、フォルダの深さで勝ち負けを決めると、ルールの SO が散らばったときに、どれが効いているかが分からなくなるため。規則を「重なったら競合」の1つにした
- **差分がなければ書き込まず、何度実行しても同じ結果にする**：自動登録は各メンバーの環境でインポートのたびに走るため、結果が揺れるとグループのアセットが git で衝突し続ける
- **ルールに当たらなくなったアセットの登録を外さない**：移動の途中や、ルールの書き換えの途中で、意図せず大量の登録が外れる事故を防ぐため。外すかどうかは利用者が決める
- **ルールの SO の変更で自動で当て直さない**：ルールの書き換えの途中（テンプレートを打っている途中など）で、プロジェクト全体の登録が書き換わるのを防ぐため。差分を見てから適用する「当て直す」を用意した
- **手で変えたエントリはルールの内容に戻す**：手で変えたことを尊重するには「手で変えた」記録が要り、その記録の置き場所が git の衝突の原因になるため。結果がいつも同じになる方を選び、例外は除外パターンで表す
- **対象フォルダを GUID で持つ**：フォルダの名前の変更や、`Samples~` を Import したときのパスの変化（`Assets/Samples/<パッケージ>/<バージョン>/...`）で外れないようにするため
- **作成時の初期値はコピーにし、評価のときに参照しない**：初期値は書く手間を省くためのもの。評価のときに Editor SO を参照すると、Editor SO を変えただけで、すべてのルールの結果が変わり、どの値が効いているかが SO を見ても分からなくなるため
- **手動一括登録を、ルールの一覧のウィンドウとは別の画面にする**：手動一括登録はフォルダを選んでその場で行う操作で、ルールの管理とは目的が違うため
- **手動一括登録は、先に全部読み込んで、不要なものを外していく流れにする**（2026-10-24）：設定（拡張子・アドレス・グループ・Label・除外）を先に決めてから読み込む形だと、設定箇所が多くて手間がかかる。先に一覧を出し、拡張子のオン／オフと行のチェックで絞り込む形なら、利用者が決めることは「追加先のグループ」と「Label」だけになる。アドレスのテンプレート・除外パターン・新規グループの Template は、画面に出さず Editor SO の値を使う。**失うもの**：手動一括登録の画面から、アドレスのテンプレートと除外パターンを変えられない（変えたいときは Editor SO を変える）
- **手動一括登録の一覧には、登録済みのアセットを出さない**（2026-10-24）：手動一括登録の目的は、まだ登録していないものを登録することで、登録済みのものを並べても、チェックを外す手間が増えるだけのため。出さなかった件数だけ知らせる。**失うもの**：画面から、登録済みのアセットのグループの移動・アドレスの書き換えができない（Addressables の Groups ウィンドウで行う）
- **Editor SO に「既定の追加先グループ」を持たせる（手動一括登録だけ）**（2026-10-24）：手動一括登録で追加先のグループを決めなかったときに、毎回同じグループに入れられるようにするため。ルールの SO は、これまでどおり空なら `DefaultGroup` で、Editor SO を参照しない（3.4 の「作成時の初期値は評価のときに参照しない」を崩さないため）
- **ルールの SO の Create メニューは `CreateAssetMenu` を使わず、独自の `MenuItem` で作る**（2026-10-24）：`ScriptableObject.Reset` が `CreateAssetMenu` からの作成で呼ばれるかに頼らず、作成のたびに確実に初期値をコピーし、対象フォルダの初期値に作った場所を入れるため（3.3）
- **グループ名を直接書く項目から「Template」という語を外す**（2026-10-24）：Addressables の Group Template（SO の参照）と紛らわしいため。グループ名を書く項目は「追加先のグループ」（コード上は `_targetGroup`）、Group Template を参照する項目は「新規グループの Template」（`_groupTemplateAsset`）とする。旧名 `_groupTemplate` は `FormerlySerializedAs` で引き継ぐ
- **標準の値は、決めた一覧だけを独自マクロとして用意する**：Addressables の `EvaluateString` に任せると、`[ ]`（ビルド時）と `{ }`（実行時）の扱いや、Addressables のバージョンによる動きの違いに左右される。決めた一覧なら、展開をピュア C# で EditMode テストでき、書き方も `{ }` の1種類で済む。**失うもの**：任意の static プロパティ・利用者が Profile に追加した変数は使えない（要望を受けて一覧に足す）
- **知らないマクロは、書かれたまま登録して警告にする**：書き間違いで登録そのものが止まると、自動登録で気づきにくい失敗になるため。プレビューと警告で気づけるようにした
- **アドレスの重複は、登録はしてエラーにする**：ルールの競合（どちらの内容で登録するかが決まらない）と違い、重複するアセットのどちらも、登録すること自体は正しいため
- **Dependency Check からは登録しない**（設計仕様書 5.3）：どのグループに入れるかは設計判断で、ルールを通さない登録は判断の根拠が残らないため。登録はルールの追加か、手動一括登録で行う
- **書き込む時点で状態を確かめ、変わっていればスキップする**（2026-10-24。レビュー指摘の修正）：手動一括登録・当て直しは、一覧や差分を見せてから書き込むまでに時間が空く。その間に別の操作で登録・移動されたエントリを、古い計画のまま書き換えないため。確かめるのは書き込みの担当（Writer）で、計画の「変更前」と今のエントリを比べる。**押した時点で計画を作り直す案は却下した**：利用者が確認したダイアログ・差分と違う内容を書くことになるため。**失うもの**：スキップしたアセットは、利用者がもう一度実行する必要がある
- **警告は、ログの細かさが「まとめだけ」のときだけ要約する**（2026-10-24）：テンプレートを変えて大量に当て直すと、「アドレスが変わります」などの警告がアセットの数だけ出て、Console が埋まり Editor も固まるため。5件を超えたら1件にまとめ（件数・最初の5件）、全件が必要なら「1件ずつ」に切り替える。エラー・競合・アドレスの重複は、件数が少ないうえに見逃すと困るため要約しない。**警告を種類ごとに要約する案は見送った**：計画の警告を種類付きの構造に変える必要があり、変更が大きいため
- **文字列の項目は、確定してから反映する**（2026-10-24）：ルールの SO と手動一括登録のウィンドウの文字列の項目に `[Delayed]` を付ける。1文字打つたびに、ルールの探し直し・プレビューの計算・重なりの警告・手動一括登録の全行の作り直しが走るのを防ぐため。**失うもの**：打っている途中では、プレビューと一覧が変わらない（Enter かフォーカスが外れたときに変わる）
- **グループ名に使えない文字の判定は、OS に依存したままにする**（2026-10-24。見送り）：どの OS でも同じ判定にするには、Windows の集合で固定すればよいが、今回は見送った。既知の制約として 11.2 に書く

## 11. 注意点・実装時に確かめること

### 11.1 注意点

- **自動登録の結果は、メンバーの環境で変わる値に左右される**：環境によって値が変わる標準の値（6.3）を使うと、メンバーごとに展開の結果が違い、インポートのたびに互いのアドレスを書き換え合う
- **アドレスの追従は、コードの文字列を壊す**：パスを使ったアドレスで追従にしていると、アセットの移動でアドレスが変わる。`[AddressablePath]` のフィールドや、コードに書いたアドレスは自動では直らない（変更前と変更後を警告に出す）
- **All はバンドルの構成を変える**：Prefab の依存まで個別のエントリになる（3.2）
- **ルールに当たるアセットの Label は、ルールの内容がすべてになる**：手で付けた Label も、次のインポートで外れる（2.3）
- グループの作成・エントリの移動は Undo で戻しにくい。当て直すと手動一括登録では、適用の前に差分・確認のダイアログを出す
- **画面の文言は表示言語に従う**（日本語・英語・利用者が足した言語。[`editor-localization-spec.md`](editor-localization-spec.md)）。Inspector の項目名（Target Group、Group Template Asset など）は、変数名から自動で付くため英語
- **区切り線の位置は完全には指定できない**：右クリックメニューの区切り線は、並び順の数字（priority）の離れ具合で Unity が決める。他のパッケージが近い数字を使うと、同じ区画に並ぶ

### 11.2 実装時に確かめたこと（Addressables 2.10.3 のソースで確認。2026-10-24）

- **Addressables の「登録できるか」の判定**（`AddressableAssetUtility.IsPathValidForEntry`）は **`internal` で、Editor アセンブリから呼べない**。同じ条件（拡張子 `.cs` `.js` `.boo` `.exe` `.dll` `.meta` `.preset` `.asmdef`、`/Editor/` の配下、設定フォルダ `ConfigFolder`）を自前で持った（7.2。`RegistrationRuleMatcher`・`RegistrationRuleScanner`）
- **Create メニューで作ったときの初期値のコピー**：`Reset` が `CreateAssetMenu` からの作成で呼ばれるかは、ソースでは確認できないため、`CreateAssetMenu` をやめ、独自の `MenuItem`（`RegistrationRuleAssetCreator`）で作る形にした。名前の入力が終わったときに、`EndNameEditAction` が初期値をコピーし、作る場所のフォルダを対象フォルダの初期値に入れる（3.3・3.4）
- **AssetPostprocessor の中での書き込み**：Addressables 自身の AssetPostprocessor は、アセットの GUID でエントリを扱い、本機能の書き込みと並び順に依存しない。再インポートの連鎖は、設定フォルダ（`ConfigFolder`）の配下のアセットを入力から除くことと、差分がなければ書き込まないことで止まる（2.1・2.2）
- **ルールの SO を探す処理のキャッシュ**：ルールの SO の追加・削除・変更のときだけ作り直す（`RegistrationRuleScanner.InvalidateRules`）。Postprocessor が、インポート・削除・移動された `.asset` を見て無効にし、ルールの SO の `OnValidate` でも無効にする
  - ルールの入力は、作った時点の対象フォルダの**パス**を持つ。そのため、**フォルダの移動・名前の変更・削除でも無効にする**（無効にしないと、名前を変えたフォルダを古いパスのまま判定し続ける）。削除されたものは種別を調べられないため、拡張子のないパスをフォルダとみなす（拡張子のないファイルでも、作り直すだけで害はない）
  - 無効にする判定は、**自動登録のスイッチの判定より前**に行う。オフの間にルールの SO を削除・追加しても、オンに戻したときに古いキャッシュが使われないようにするため
- **Addressables のグループ名に使えない文字**：Addressables 自身は、グループ名の `/` と `\` を `-` に置き換えるだけで、ほかの検証をしない。本機能は、ファイル名に使えない文字（`Path.GetInvalidFileNameChars`）を含むと、登録せずエラーにする（6.5。`RegistrationMacroExpander.IsValidGroupName`）。Windows 以外では、使えない文字の集合が小さい
  - **既知の制約**：判定が OS に依存するため、Windows 以外のメンバーは、Windows では使えない文字（`*` `?` `"` `<` `>` `|` `:` など）を含むグループ名で登録できてしまう。そのグループのアセット（`.asset`）は、Windows のメンバーがチェックアウトできない。OS の混ざったチームでは、グループ名（とマクロを展開した結果）に、どの OS でも使える文字だけを使うこと（10章）
- **エントリへの書き込みのまとめ方**：各操作では `postEvent = false` を渡して通知を止め、最後に `SetDirty(ModificationEvent.BatchModification, null, true, true)` を1回だけ呼ぶ（`RegistrationEntryWriter`）
- **スキップの知らせ方**：スキップは1件ずつ Console に出さず、件数だけを1件の警告で知らせる（大量にあると Console が埋まるため）。ウィンドウは書き込みのあとに自動で一覧を作り直すため、知らせの文言は「内容を確かめて、もう一度実行してください」とする
